# ClanChat

Клановая система для Fabric-клиента Minecraft **26.1.2** с чатом в стиле
Discord/Telegram: роли, инвайты, права, и вложения к сообщениям (координаты,
инвентарь, эндер-сундук, предмет в руке, статус здоровья).

**Мод целиком клиентский.** Он не устанавливается на Minecraft-сервер и не требует
доступа к его файлам — вся клановая логика и хранение данных живут на отдельном
WebSocket-бэкенде (папка [`/backend`](backend/), Node.js), который можно развернуть
где угодно (например, на Wispbyte). Это специально сделано так, чтобы мод работал
на сервере с любым ядром — Paper, Spigot, Purpur и т.д., — где Fabric-моды физически
не ставятся.

Открывается по умолчанию клавишей **C** (переназначается в Настройки → Управление →
ClanChat, либо через экран настроек мода в ModMenu — там же указывается адрес бэкенда).

## Возможности

- **Кланы**: создание, роспуск, инвайты, кик, роли (Лидер/Офицер/Участник) с
  настраиваемыми правами, передача лидерства.
- **Чат**: каналы Клан / Офицеры / Личные сообщения / Системные уведомления.
- **Вложения к сообщению**: координаты, предмет в руке, весь инвентарь, эндер-сундук,
  статус здоровья (авто-флаг "нужна помощь" при HP < 30%).
- Персистентность кланов на бэкенде (простой JSON-файл, см. `backend/README.md`).

## Архитектура

```
[Клиент 1] ─┐
[Клиент 2] ─┼── WebSocket ──> [backend/, Node.js, где угодно] ── clans.json
[Клиент N] ─┘
```

Мод НЕ общается с самим Minecraft-сервером напрямую — соединение с бэкендом
устанавливается независимо, при входе в любой мир, и продолжает работать даже если
игрок прыгает между разными серверами. Идентификация — по нику, без криптографической
проверки Mojang-сессии (подробности и обоснование — в `backend/README.md`); это
осознанный компромисс, так как не у всех игроков есть лицензия.

## Стек

- Minecraft 26.1.2, Fabric Loader 0.19.3, Fabric API 0.155.2+26.1.2, Java 25.
- Официальные маппинги Mojang.
- Встроенный в JDK `java.net.http.WebSocket` — никаких доп. зависимостей на клиенте.
- Бэкенд — Node.js + `ws`, см. [`backend/README.md`](backend/README.md) для деплоя.
- Опциональная интеграция с [ModMenu](https://modrinth.com/mod/modmenu) для экрана
  настроек (мод работает и без ModMenu).

## Сборка мода

```
./gradlew build
```

Готовый джарник — в `build/libs/`. Сборка проверена в CI (GitHub Actions, см.
`.github/workflows/build.yml`) и **проходит зелёным**.

## Запуск бэкенда

```
cd backend
npm install
npm start
```

Подробности и деплой на Wispbyte — в [`backend/README.md`](backend/README.md).
Протокол (весь набор действий) сверяется по `src/main/java/.../network/ClanAction.java`
на стороне мода — при изменении протокола нужно поправить оба конца.

## Что было исправлено при первой реальной сборке мода

Изначальный код был написан без доступа к Maven-репозиториям Mojang/Fabric, поэтому
несколько мест пришлось поправить по фидбеку CI:

- `modImplementation` → `implementation` (в Fabric Loom 1.17.x, с официальными
  Mojang-мэппингами без Yarn-ремаппинга, отдельных mod-конфигураций больше нет).
- `.getGameProfile().getName()` → `.getName().getString()`.
- `Player#displayClientMessage(...)` → `Player#sendSystemMessage(...)` на клиенте.
- `ResourceKey#location()` → `ResourceKey#identifier()` (переименован вслед за
  `ResourceLocation` → `Identifier`).
- Прямой доступ к приватному полю `Inventory#items` заменён на
  `getContainerSize()`/`getItem(i)`.
